# Contributing to Code Scaffold

## Soft-Closed Repository Policy

Thank you for your interest in contributing to Code Scaffold! 

Code Scaffold operates under a **"Soft-Closed" Repository Ownership Policy**. This means that while the source code is entirely public, available for your use, and completely transparent, the core repository architecture and strategic roadmap are tightly controlled by the core team.

### What does this mean for you?

1. **Pull Requests:** We do **not** accept unsolicited pull requests for new features, major architectural changes, or codebase refactoring. Any such PRs will be politely closed.
2. **Issues & Bug Reports:** We highly encourage you to open issues for bug reports, security vulnerabilities, or well-documented edge cases.
3. **Forks:** You are absolutely free to fork this repository, build your own custom agent workflows, and modify the UI to fit your own pipeline needs in accordance with our licensing.
4. **Skills Ecosystem:** If you build an incredible custom `.skill`, you are encouraged to publish it on your own repository. Code Scaffold's `skills-cli` architecture allows users to pull skills from *any* remote repository on demand, meaning your contributions can live outside the core repository and still natively extend Code Scaffold!

### AI Agent Operations

To ensure absolute pipeline stability, human PRs that conflict with the agent's structural memory or established rule mappings (`AGENTS.md`) are strictly restricted.

Thank you for understanding and supporting our mission to build a hyper-secure, agent-first development harness!
