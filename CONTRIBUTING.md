# Contributing to Code Scaffold

Thank you so much for your interest in contributing to **Code Scaffold**! We deeply appreciate the community's enthusiasm and support for this project.

## Our Philosophy

Code Scaffold is built with a highly curated, hyper-opinionated core architecture. The overarching goal is to maintain absolute structural integrity, strict deployment predictability, and rapid iteration pipelines.

To preserve this unified architectural vision and maintain full ownership over the repository's evolution, **we do not accept or merge external Pull Requests (PRs) that modify the core codebase or framework.**

## How You Can Contribute

While direct PRs are soft-closed, your input is still incredibly valuable to the project! We encourage the community to contribute in the following ways:

### 1. Ideas & Feature Requests
Have an idea for a new Skill or deployment pipeline? We'd love to hear it! Please open an **Issue** tagged as an `enhancement`. Describe the use case, the proposed architecture, and how it fits into the broader Code Scaffold ecosystem. We regularly review these ideas to inform the official roadmap.

### 2. Bug Reports
If you encounter a bug, unexpected behavior, or a failure in one of the automated tests (like the headless VHS recordings), please open an **Issue** tagged as a `bug`. 
Include:
* A clear description of the issue.
* Steps to reproduce.
* The OS and environment you are running on.
* Any relevant terminal output or logs.

### 3. Discussions
Join the conversation! Feel free to open a **Discussion** (if enabled) or an Issue to ask questions, share how you are using Code Scaffold, or discuss potential architectural patterns.

---

By funneling community involvement into ideas and issue-reporting, we ensure that every line of code added to Code Scaffold aligns perfectly with its overarching mission. Thank you for being a part of this journey!
